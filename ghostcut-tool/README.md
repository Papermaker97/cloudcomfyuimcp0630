# 고스트컷 자동 생성 툴

모델 착장 이미지를 **여러 장** 넣으면, 각 장마다 상품 단독 누끼 PNG가 하나씩 나오는 웹 툴.
사용자는 ComfyUI를 전혀 보지 않는다.

---

## 지금 상태

| 항목 | 상태 |
|---|---|
| 웹 UI (여러 장 업로드, 장당 결과 카드, 원본/결과 토글, 개별·일괄 저장) | ✅ 브라우저에서 실제 구동 확인 |
| 데모 모드 (네트워크 없이 동작) | ✅ 4장 투입 → 4장 출력 확인, 콘솔 에러 0건 |
| 브릿지 서버 (multipart 파싱, CORS, 에러 응답, 결과 서빙) | ✅ 실제 실행해 엔드포인트 확인 |
| **ComfyUI 실제 호출** | ⚠️ **미검증** — 아래 §4 참고 |

---

## 1. 데모 모드로 바로 쓰기 (설치 불필요)

`index.html` 을 브라우저로 열면 끝. 서버도 인터넷도 필요 없다.

1. 왼쪽에 착장 이미지 여러 장을 드래그
2. 아이템(상의/하의/스커트/원피스/자켓)과 배경(투명/흰색) 선택
3. **생성하기**
4. 카드마다 결과가 뜨고, 원본/결과 토글과 다운로드 버튼이 생김

`assets/demo_01.png` ~ `demo_04.png` 를 순서대로 보여준다.
지금 들어 있는 건 **자리표시자**이므로, **강사님이 실제로 뽑은 고스트컷 결과 4장으로 교체**하면
시연에서 진짜 결과가 나오는 것처럼 보인다. 파일명만 맞추면 된다.

> 라이브에서 절대 안 터지는 모드다. 인터넷·크레딧·API가 개입하지 않는다.

---

## 2. 라이브 모드 (진짜 생성)

### 왜 서버가 필요한가

브라우저에서 Comfy를 직접 부를 수 없다. API 키가 프론트엔드에 노출되고, CORS에도 막힌다.
그래서 `server.py` 가 중간에서 대신 호출한다.

### 실행

```bash
python3 server.py
```

macOS 기본 python3로 돌아간다. **pip 설치가 필요 없다** (표준 라이브러리만 사용).

그다음 `index.html` 상단의

```js
const LIVE = false;
```

를 `true` 로 바꾸고 브라우저를 새로고침한다. 헤더의 표시가 "라이브 모드"로 바뀐다.

### 접속 대상 지정

```bash
COMFY_HOST="http://127.0.0.1:8188" python3 server.py
COMFY_API_KEY="키" COMFY_HOST="https://..." python3 server.py
```

## 3. 동작 흐름

```
브라우저                    server.py                   ComfyUI
   │                            │                          │
   ├─ 이미지 N장 ──────────────>│                          │
   │  (한 장씩 순차 전송)        ├─ /upload/image ─────────>│
   │                            ├─ /prompt ───────────────>│
   │                            │<── prompt_id ────────────┤
   │                            ├─ /history/{id} 폴링 ────>│
   │                            ├─ /view ─────────────────>│
   │                            │<── PNG ──────────────────┤
   │<── 결과 URL ───────────────┤  assets/out/ 에 저장      │
   │  카드에 표시                │                          │
```

한 장이 실패해도 나머지는 계속 진행하고, 실패한 카드에만 사유가 표시된다.
실패한 것만 다시 **생성하기** 를 누르면 재시도된다.

## 4. ⚠️ 검증되지 않은 부분

`server.py` 의 ComfyUI 호출은 **표준 ComfyUI HTTP API** 기준으로 작성했다.

```
POST /upload/image     이미지 업로드
POST /prompt           워크플로우 실행
GET  /history/{id}     상태 확인
GET  /view             결과 이미지
```

이건 로컬 또는 자체 호스팅 ComfyUI에서는 표준이다. 하지만
**Comfy Cloud의 인증 방식과 엔드포인트는 이 환경에서 확인하지 못했다**
(문서 사이트 접근이 막혀 있었다). 지어내지 않고 표준 API로 두었으니,
Comfy Cloud에 붙이려면 다음을 확인해야 한다.

- 인증 헤더 이름과 형식 (현재는 `Authorization: Bearer <키>` 로 가정)
- 위 4개 엔드포인트의 실제 경로
- 응답 JSON 구조

수정할 곳은 `server.py` 의 `upload_image()`, `submit()`, `wait_and_fetch()` 세 함수뿐이다.

**로컬 ComfyUI가 있다면 수정 없이 그대로 동작한다.**

## 5. 파일 구성

```
ghostcut-tool/
├─ index.html          웹 UI (이것만 열면 데모 모드로 동작)
├─ server.py           브릿지 서버 (라이브 모드용, 표준 라이브러리만)
├─ workflow.api.json   ComfyUI 워크플로우
└─ assets/
   ├─ demo_01~04.png   데모 모드 결과 (실제 결과로 교체할 것)
   └─ out/             라이브 모드 결과 저장 위치
```

---

## 6. 워크플로우와의 대응

`server.py` 는 요청마다 `workflow.api.json` 의 값을 바꿔 넣는다.

| UI 조작 | 바뀌는 곳 |
|---|---|
| 이미지 업로드 | 노드 `1` LoadImage `image` |
| 아이템 선택 | 노드 `7` `prompt` 의 `the SAME top` → `the SAME pants` 등 |
| 배경 선택 | 노드 `8` `background` = `Alpha` / `Color`(흰색) |
| (매 실행) | 노드 `7` `seed` 를 매번 새로 지정 |

---

## 7. 시연에서 밝힐 한계

- 가려졌던 부분은 **AI의 추정**이지 복원이 아니다.
- 패턴·봉제선·로고·색상이 실제 상품과 달라질 수 있다.
- 상품 등록·납품 전에는 디자이너 검수가 필수다.
- 생성에는 크레딧이 소모된다 (이미지 1장당 약 8.6 크레딧).
